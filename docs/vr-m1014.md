# M1014 individual-shell reload

M1014 uses a separate fixed-tube feed authority (`tube_feed`, `tube_gesture`,
`tube_runtime`, `tube_presenter`). The existing native detours dispatch to each
feed family; this adapter does not describe a shell as a detachable magazine.

## Interaction

- Pinch with the trigger at the existing body ammunition supply to draw one
  shell. Release and pinch again to draw the next shell.
- With the bolt locked open, put the shell at the right ejection/loading port:
  it chambers directly and releases the bolt. Presentation eases the bolt home
  over 100 ms; the transition adds no firing or input cooldown.
- The underside loading port adds only to the fixed tube. It accepts ordinary
  top-ups; loading there while locked open preserves the lock and empty chamber.
- Pull the right bolt handle farther rearward, then release, to feed a stored
  shell and leave the lock. Merely grabbing the open handle is insufficient.
- A full rack ejects a live chambered shell once; a short pull leaves it intact.
  Releasing a full rack feeds one stored shell, or returns to empty lock.
- The tube holds seven shells plus a separate chamber. Native initial totals
  are partitioned (seven initially means six in the tube and one chambered).
  Topping up supports seven plus one. The last shot retains the bolt open.

These are the requested game interaction rules. No additional carrier-release
button, ghost loading, pump action or multi-shell hand loading is implied.

## Ownership and integration

The authoritative state separately retains stored count, chamber, bolt phase,
reserve and a one-shell hand escrow. It uses the shared compared native ammo
writes, input press gate, constrained bolt travel, hand mirroring, anatomical
hand solver, body supply volumes, sound/haptics and scene part submission.

Only explicitly registered M1014 descriptors with segmented reload and a
one-round addition are admitted. Native auto-reload is intercepted. Native
semi-auto cadence and pellet generation remain unchanged; one shot spends one
shell. Independent dual-wield firing checks the relevant tube instance.

The shared reload boundary also intercepts `PM_BeginWeaponReload`, before the
segmented prelude can emit sounds, select animation 71 or enter state 11.
Native automatic empty reload can bypass the ordinary admission check; blocking
only the later refill/normal-reload leaves produces repeated start/end cycles.
`vr_reload_status` includes blocked begin counts for server and prediction.

Native shape decoding uses `WeaponDef::segmentedReload` at `0xE96`; the adjacent
`0xE95` is `noPartialReload`. Both offsets are checked against the C++ layout and
their separate engine accessors. Regression tests reconstruct the captured
`00 01` flag pair so partial-reload permission cannot disable tube admission.

Hand transfer and drop/pickup preserve tube/chamber partition and bolt phase.
Interruptions refund an escrowed shell and close a manually held action before
ownership moves. Failed writes preserve authoritative state. A failed insertion
requires withdrawal and fresh contact, and a tracking jump cannot insert.
New input generations establish neutral baselines rather than replaying pinches.

The held shell is the receiver's own `tag_clip` geometry, moved in the exact
hand skeleton pose. Its visibility follows the current hand escrow. Released
or manually ejected shells use a bounded, depth-tested rigid subset and the
existing gravity drop trajectory; these are short-lived cosmetic objects.
Their lifetime and ammunition-disposal policy match existing loose reload parts.

## Native and offline evidence

The  read-only shotgun capture contains `m1014`, `m1014_arctic`,
`m1014_reflex` and `m1014_eotech`: capacity seven, segmentedReload one,
reloadAmmoAdd one, non-bolt-action semi-auto firing and eight pellets.
Native wrappers use `h2_viewmodel_benelli_m4_base` or its `_arctic` variant.
The two exports have identical bone transforms and single-shell vertices.

| Part | Bone | Parent |
| --- | --- | --- |
| Bolt and actual right-side handle | `j_bolt` | `j_gun` |
| Underside lifter | `j_load` | `j_gun` |
| One complete reload shell | `tag_clip` | `j_gun` |

Both receivers have 12 bones. The shell subset contains 287 triangles.
Test data retain receiver hashes; pose headers retain animation hashes.

- Idle hand poses: `h2_wpn_sho_m1014_idle`, frame 0.
- Shell hand pose: shared `h2_wpn_sho_spas12_reload_loop`, frame 6, including
  the complete canonical-left finger chains and rigid shell-in-wrist transform.
  The M1014 shell retains its own geometry; its bounds center is aligned to the
  SPAS shell before applying that transform. Its measured nearest skinned contact
  is 2.192 mm in the offline reference glove. Ports, rack and feed rules remain
  M1014-specific. The same anatomical mirror path supports the other hand.
- Rack hand poses: left index and reverse pinky hooks share the AK family fit.
  The existing right index grasp retains the M14 EBR `reload_empty`, frame 73
  wrist and complete 18-joint pose. The right reverse pinky hook is independently
  fitted at the same real handle. M1014's native release-button gesture is not
  used for physical racking. The tube profile exposes both styles; acquisition
  records the chosen style, and simulation/rendering retain it until release.
- Empty action: `empty_additive` moves the bolt rearward 104.333 mm. Manual
  overtravel adds 6 mm, with the release threshold 3 mm beyond the lock.
- Loading centers follow native shell approaches: side approximately
  (19.394, -3.2, 9.448) cm, underside (18.029, -0.169, 3.2) cm, gun-local.
  Separate 3.5 cm contact radii do not overlap; shell direction must agree
  with the corresponding source insertion direction.

Only authored hand poses mirror. The actual right-side handle and loading port
remain on the right of the receiver. Idle/rest action poses override original
reload/equip animations within the existing local hand presentation boundary.

When the left hand carries only the fore-end, the right rack hand still publishes
its part lease. Both hook styles also mark the constrained hand as posed, so the
later empty-hand pass cannot overwrite its wrist or fingers. The subsequent
[comfort pass](vr-interaction-comfort.md) redirects the index at its root only
in the left-down/right-up pinky-hook style. The index-hook style and original right index fit
retain their positions.

## Validation and remaining headset acceptance

`tube_reload_tests.hpp` tests both hands, seven-plus-one, both empty reload
paths, live extraction, short strokes, held-rack deduplication, style latching,
invalid style rejection, preserved right index poses, capacity limits,
stale identity, duplicate input, failed native writes, tracking jumps, focus
loss and transfer snapshots. `m1014_profile_tests.hpp` checks 56 assembly
combinations, complete hand/part binding, actual-side mirroring and disjoint
loading contacts. Existing physical reload, weapon grip, weapon mechanics,
native HUD and rigid-part/WARP suites pass; Debug x64 client compiles.

`vr_tube_status` reports current tube/chamber/reserve/hand counts, phase, rack
travel and rejection reason. `vr_tubeReload` controls the adapter, enabled by
default. Headset acceptance still needs the two insertion positions, pinch
pose, bolt reach/return, first-person shell visibility and hand transfer checked
against live tracking. Offline contacts and state tests cannot establish comfort.

Shell grasp refinement is deferred to the remaining shotgun adapters, where
a common individual-shell hand pose can be evaluated and shared.
